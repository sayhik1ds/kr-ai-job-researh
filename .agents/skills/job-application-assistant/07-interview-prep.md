# 면접 준비 형식

`/interview`가 `applications/<회사>_<포지션>/`의 제출본과 공고를 읽어 `interview/<회사>_<포지션>.md`를 만든다.

## 원칙

- 제출한 문서에 쓴 내용만 준비 대상이다. 제출본에 없는 경험을 답변에 넣지 않는다
- 설계 제안과 실제 구현을 구분한다. 구현한 것은 PR·커밋 근거를 옆에 적는다
- 확인 안 된 내용은 "확인 후 보완"으로 표시한다
- 격차 질문에는 인정하고 인접 경험을 말한다. 없는 경험을 있는 것처럼 답하지 않는다

## 출력 구조

```
# [회사] [포지션] 면접 준비

## 공고 요건 대조
| 요건 | 제출본 근거 | 상태 |
|---|---|---|
| ... | 포트폴리오 케이스 2 | 충족 |
| ... | 없음 | 격차 |

## 예상 질문 (10개)

### Q1. [질문]
- **왜 나올 질문인가:** 공고 "..." 문장
- **답변 (구술 60~90초):** ...
- **근거:** 포트폴리오 케이스 N, PR #...
- **꼬리 질문:** ...

## 격차 질문
### Q. Kafka 운영 경험이 있나
- **답변:** 없다. 인접 경험은 ...

## 역질문 5개
- ...

## 확인 후 보완
- [ ] ...
```

## 기술 질문 유형

- 제출본 수치의 측정 조건 (부하 테스트 환경, 데이터 규모)
- 성능 개선 사례의 전후 비교와 병목 진단 방법
- 장애 대응 사례의 탐지·원인·재발 방지
- 설계 선택의 대안과 기각 이유
- 공고 필수 스택 중 격차 항목
