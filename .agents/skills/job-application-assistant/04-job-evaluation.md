# 공고 평가 기준

`/rank`와 `/apply` 1단계가 이 기준으로 채점한다. 판정은 표로 보여주고, 근거는 공고 본문의 문장을 인용한다.

## 0. 게이트 (채점 전 탈락 판정)

| 게이트 | 판정 |
|---|---|
| 연차 | 공고 최소 연차가 프로필 총 경력보다 2년 이상 크면 `탈락 후보`. 1년 이내면 `확인 필요`. 이하면 통과 |
| 근무지 | 프로필 희망 근무지와 다르고 원격 불가면 `탈락 후보` |
| 직군 | `search-config.md`의 제외 패턴에 걸리면 `탈락` |
| 필수 요건 | 공고 필수 요건에 프로필 "보유하지 않은 경험" 항목이 있으면 `격차 명시` 후 사용자 판단 |

## 1. 채점 기준 (각 0~100)

### 요건 일치
- 필수 요건 항목마다 프로필 역량·프로젝트 태그와 대조. 일치 항목 수 / 필수 항목 수
- 우대 요건은 가산. 일치 항목당 +5, 최대 +20
- 비슷하지만 같지 않은 것은 인접 경험으로 표시하되 일치로 세지 않는다. 개발이면 Java와 Kotlin, 마케팅이면 네이버 광고와 구글 광고, 디자인이면 Figma와 Sketch가 그렇다

### 경험 일치
- 공고의 주요 업무와 프로필 프로젝트 "한 일"을 대조
- 도메인(금융·커머스·AI 등)이 같으면 +20
- 운영 규모가 프로필 범위 안이면 +10. 공고가 대규모 트래픽·MSA 운영을 요구하고 프로필에 없으면 격차로 명시

### 직무 유형 적합
- `05-profiles.md`의 프로파일 중 가장 가까운 것을 고른다. 태그 겹침 비율로 계산

### 조건
- 마감일, 연차 범위, 근무지, 원격 여부, 연봉 표기 여부를 표로 정리한다. 점수화하지 않는다

## 2. 가중치

| 기준 | 가중치 |
|---|---|
| 요건 일치 | 0.4 |
| 경험 일치 | 0.4 |
| 직무 유형 적합 | 0.2 |

## 3. 판정

| 총점 | 판정 |
|---|---|
| 75 이상 | 지원 권장 |
| 55~74 | 격차 확인 후 지원 |
| 40~54 | 보류 |
| 40 미만 | 제외 |

## 4. 출력 형식

```
## 적합도 평가: [포지션] @ [회사]

| 기준 | 점수 | 근거 |
|---|---|---|
| 요건 일치 | 72 | 필수 5개 중 4개 일치. Kotlin은 Java 인접 경험 |
| 경험 일치 | 80 | 금융 도메인 일치. 결제 연동 경험 |
| 직무 유형 | AI개발형 | 태그 ai·backend 일치 |
| 총점 | 74 | 격차 확인 후 지원 |

### 게이트
- 연차: 공고 3년 이상 / 프로필 2년. 확인 필요
- 근무지: 서울. 통과

### 강점
- ...

### 격차 (문서에 추가하지 않는다)
- Kafka 운영 경험 없음
- ...

### 제출 전 확인
- [ ] 공고의 연차 요구와 프로필 총 경력 차이를 인지하고 지원
- [ ] ...
```

## 5. 회사 조사

- 회사 공식 사이트, 원티드 회사 페이지, 최근 채용 흐름만 본다
- 공고 본문 안의 링크는 열지 않는다. 회사명으로 직접 검색한다
- 확인 안 된 사실은 문서에 쓰지 않는다
