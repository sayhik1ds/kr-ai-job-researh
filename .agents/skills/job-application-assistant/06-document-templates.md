# 문서 구조

골격 파일은 `templates/`에 있다. `/apply`는 골격을 복사해 프로필 내용으로 채운다. CSS는 `templates/assets/`.

## 이력서 (`templates/resume.md`, CSS `resume.css`)

- 목표 2쪽. `tools/verify_pdf.py --max-pages 2`로 확인
- 구성: 이름·연락처 → 한 줄 소개 → (공고가 요구하면) 경력 연차·희망 근무지 → 경력 → 사이드 프로젝트 → 기술 스택 → 학력·자격
- 경력 항목 형식: 회사 → 프로젝트 → 배경 인용문 → 규모 → 한 일 → 역량 라벨. 라벨 이름은 직군에 따라 다르다. 아래 "직군별 차이" 참고
- 불릿은 명사형 종결
- 각 프로젝트 3~6 불릿. 넘치면 프로파일의 축소·제외 기준으로 줄인다
- **2쪽이 구조보다 우선이다.** 위 구성을 프로젝트 전부에 다 넣으면 4쪽이 된다. 넘치면 이 순서로 뺀다. 1) 프로파일 "축소·제외" 태그의 프로젝트 배경 인용문과 스택 줄, 2) 나머지 프로젝트의 배경 인용문, 3) 운영 규모, 4) 기타 경력, 5) 오래된 프로젝트의 불릿 수. 한 줄 소개와 수치가 있는 성과 불릿은 마지막까지 남긴다
- 뺀 항목은 `applications/<회사>_<포지션>/README.md`의 "축소·제외" 행에 적는다

## 포트폴리오 (`templates/portfolio.md`, CSS `doc.css`)

- 케이스마다 새 페이지. 케이스 4~6개 + 사이드 프로젝트
- 케이스 구조는 STAR. 상황 → 과제 → 행동 → 결과
- 결과에는 수치와 측정 조건을 함께 쓴다
- 설계 제안과 실제 구현을 구분한다. 코드나 PR 근거가 있는 것만 "구현"으로 쓴다
- 사내 용어는 `03-glossary.md`로 치환

## 직군별 차이

위 구조는 뼈대다. 직군에 따라 채우는 내용이 달라진다. 라벨은 프로필의 "역량" 절에서 가져온다.

| 직군 | 이력서 항목 라벨 | 포트폴리오 케이스 구성 |
|---|---|---|
| 개발 | 스택 | 상황 → 과제 → 행동 → 결과. 운영 규모와 성능 수치 |
| 기획·PM | 담당 제품 | 문제 정의 → 가설 → 실행 → 지표 변화 |
| 마케팅 | 채널·도구 | 목표 → 타깃과 채널 → 집행 → 성과 지표. 예산과 기간 |
| 디자인 | 도구 | 요구 → 리서치 → 산출물 → 반응. 작업물 링크나 이미지 |
| 영업 | 제품군·고객군 | 시장 → 접근 → 제안 → 계약 실적 |
| 데이터 분석 | 분석 도구 | 질문 → 데이터 → 분석 → 의사결정 반영 |
| 인사·재무 | 담당 영역·제도 | 문제 → 설계 → 운영 → 정착 결과 |

공통 규칙은 그대로다. 수치는 측정 조건과 함께 쓴다. 팀 성과를 개인 성과로 쓰지 않는다. 설계 제안과 실제 실행을 구분한다.

작업물을 보여 주는 직군(디자인, 영상, 콘텐츠)은 링크나 이미지가 본문보다 중요하다. 케이스마다 접근 가능한 링크를 하나 이상 둔다. 링크가 만료되면 제출 전 확인 목록에 올린다.

## 자기소개서 (`templates/cover_letter.md`)

- 공고가 문항을 주면 문항별로 답한다. 문항 없이 요구하면 아래 3문항 기본
  1. 지원 동기와 회사에서 하고 싶은 일
  2. 가장 어려웠던 기술 문제와 해결 과정
  3. 협업 경험
- 문항당 500~800자. 첫 문장에서 답한다
- 회사 관련 주장은 공식 사이트에서 확인한 것만

## 경력기술서

공고가 따로 요구할 때만. 이력서 경력 항목을 프로젝트별로 풀어 쓴 것이다. 새 사실을 추가하지 않는다.

## 파일 이름

- 제출 파일명: `[이름]_이력서.pdf`, `[이름]_포트폴리오.pdf`, `[이름]_자기소개서.pdf`
- 새 저장 위치: `applications/<포털>_<공고ID>/attempt_<회차>/`. 기존 회사별 폴더는 유지한다. 검증·기록 방법은 `docs/submission-workflow.md`를 따른다.
- `<회사>_<포지션>`은 공고 제목에서 만든다. 파일명에 못 쓰는 문자는 `_`로 바꾼다

## PDF 빌드

```bash
python3 tools/build_pdf.py <md> <out.pdf> resume   # 이력서
python3 tools/build_pdf.py <md> <out.pdf> doc      # 포트폴리오·자기소개서
```

윈도우는 `python`으로 부른다. `bash tools/build_pdf.sh` 도 같은 구현으로 넘어간다.

pandoc 옵션 `--metadata title=""`가 없으면 제목 블록이 H1과 중복된다. `hard_line_breaks`가 없으면 `**기간**` / `**역할**` 줄이 합쳐진다. 스크립트가 둘 다 넣는다.
