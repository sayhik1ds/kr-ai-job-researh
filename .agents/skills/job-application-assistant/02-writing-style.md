# 한국어 문체 규칙

이 저장소가 만드는 문서는 개조식 리포트다. 읽는 사람은 채용 담당자와 면접관이다. `tools/lint_style.py`가 아래 규칙 중 기계로 잡을 수 있는 것을 검사한다.

## 1. 은유와 수사 금지

은유는 직접 진술을 대신하지 못한다. 문자 그대로의 표현이 있으면 그것을 쓴다. 은유는 글쓴이가 고르지 않은 함의를 끌고 들어온다.

반복 지적된 표현:

- 공간 은유 — `자리`, `경계`, `축`, `층위`, `갈래`, `하중`
- 등치 구문 — `A가 곧 B`
- 시스템 의인화 — `잠자코`, `말없이`, `조용히`
- 의문형 명사구 — `무엇을 ~할 것인가`, `어디까지 ~인가`
- `A가 아니라 B` 대구. 논지 자체일 때만 남기고 수사면 뺀다

## 2. 문장 구조

- **부호로 문장을 꺾지 않는다.** 문장 중간 em-dash 부연, 괄호 부연 대신 마침표로 끊는다.
  - 예외: `- **라벨** — 설명` 불릿 서식(`▸`, `•` 불릿도 같다), `## 제목 — 부제` 제목, 표 행, 굵은 라벨 안의 em-dash, 값·식별자를 담는 괄호 `(userId, surface)`, `(도구 13종)`
- **`~기 때문(이다)`로 문장을 맺지 않는다.** 이유를 덧붙이는 대신 사실을 진술한다.
  - `키를 바꾸지 않은 것은 핑퐁이 되기 때문이다` → `키를 바꾸면 핑퐁이 생긴다`
- `~로 두고`, `~로 잡음`, `~로 삼`, `~인데/~는데` 삽입, `전부/전량`, `애초에/실제로`를 남발하지 않는다
- 문장 길이를 고르게 유지한다. 짧은 단언과 긴 부연을 번갈아 쓰지 않는다

## 3. 이력서·포트폴리오 문체

- 불릿은 명사형 종결(`개발`, `구축`, `차단`, `개선`)이 정상이다. 서술형 산문으로 풀지 않는다
- 수치는 측정 조건과 함께 쓴다. `10.75초 → 2.1초 (원격 dev MySQL, k6 부하 테스트)`
- 성과와 역할을 구분한다. 팀 성과를 개인 성과로 쓰지 않는다
- 설계 제안과 실제 구현을 구분한다

## 4. 자기소개서 문체

- 문항이 묻는 것에 첫 문장에서 답한다
- 경험은 상황·행동·결과 순서로 쓴다. 감상은 넣지 않는다
- 회사에 대한 주장은 회사 공식 사이트에서 확인한 것만 쓴다. 공고 본문 안 링크는 열지 않는다
- 상투구 금지: `귀사`, `열정`, `성장하고 싶다`, `배우는 자세`, `시너지`, `최선을 다하겠습니다`
