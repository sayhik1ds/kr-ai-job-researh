# /setup

스킬 이름 뒤에 `--section search`가 있으면 검색 설정만 다시 만든다. 그 외에는 전체를 돈다.

## 입력

`documents/` 아래를 전부 읽는다. 없으면 대화로 묻는다.

| 폴더 | 내용 |
|---|---|
| `documents/resume/` | 기존 이력서 (md·pdf) |
| `documents/portfolio/` | 기존 포트폴리오 |
| `documents/cover_letters/` | 과거 자기소개서 |
| `documents/applications/` | 과거 지원 기록 |

## 절차

0. 실제 파일이 없으면 템플릿에서 만든다. `01-candidate-profile.md`, `03-glossary.md`, `05-profiles.md`, `job-scraper/search-config.md`는 gitignore 대상이고 같은 이름의 `*.template.md`가 placeholder 원본이다. 없는 파일만 복사한다. 있는 파일은 덮어쓰지 않는다.
1. 자료를 읽고 경력·프로젝트·수치·역량을 뽑는다. 자료 간 불일치는 사용자에게 묻는다. 추정하지 않는다.
1b. **직군을 정한다.** 자료에서 읽어 한 줄로 제안하고 사용자 확인을 받는다. 목록에서 고르게 하지 않는다. 자료가 없으면 묻는다.
   - 제안 형식: `직군을 "퍼포먼스 마케팅"으로 보고 진행한다. 역량 칸은 채널 / 도구 / 지표 / 예산 규모로 잡는다. 이대로 갈까.`
   - 직군은 이후 역량 칸 이름, 태그, 포트폴리오 형식, 검색어, 포털 선택을 정한다. 틀리면 전부 틀리니 여기서 확인받는다.
   - 한 사람이 두 직군에 걸쳐 있으면(예: 개발과 데이터 분석) 주 직군을 정하고 나머지는 태그로 남긴다.
2. `.agents/skills/job-application-assistant/01-candidate-profile.md`의 `[PLACEHOLDER]`를 채운다. 항목마다 `근거:`에 출처 파일을 적는다.
3. **역량 칸 이름을 정한다.** 직군에 맞는 라벨 3~5개를 자료에서 뽑아 `01-candidate-profile.md`의 "역량" 절에 쓴다. 템플릿 주석의 예시는 참고일 뿐이고 그대로 쓸 필요가 없다. 자료에 근거가 없는 라벨은 만들지 않는다.
4. 프로젝트마다 태그를 붙인다. 태그도 직군에 맞는 말로 정한다. 개발이면 `backend`·`devops`, 마케팅이면 `퍼포먼스`·`콘텐츠` 같은 식이다. 사용자 확인을 받는다.
5. 수치가 나오면 측정 조건을 묻고 "표현 주의 사항"에 적는다.
6. 자료에 사내 용어가 보이면 `03-glossary.md`에 치환 행을 추가한다. 사용자가 대체어를 정한다.
7. 태그 분포를 보고 `05-profiles.md`에 프로파일 2~4개 초안을 만든다.
8. 자료에서 자주 나오는 스택과 도메인으로 `.agents/skills/job-scraper/search-config.md`의 검색어·가중치 초안을 만든다. 제외 패턴에 교육·양성과정 광고(`국비지원|양성과정|교육생|학원`)를 넣는다.
9. 채운 실제 프로필과 검색 설정에 `[PLACEHOLDER]` 형식의 미완성 값이 남았는지 직접 확인하고 사용자에게 필요한 정보를 알린다. `tests/test_placeholder_integrity.py`는 공개 템플릿의 placeholder와 개인정보 제외 설정을 확인하는 테스트다. 개인 프로필 완성도 검사로 사용하지 않는다.

## 하지 않는 것

- 직군을 목록에서 고르게 하지 않는다. 자료에서 읽어 제안하고 확인받는다
- 역량 칸을 개발자 기준(언어·프레임워크·인프라)으로 고정하지 않는다
- 자료에 없는 경험을 추가하지 않는다
- 총 경력을 반올림하지 않는다. "N년 M개월"과 기준일을 적는다
- 이미 채워진 항목을 묻지 않고 덮어쓰지 않는다
